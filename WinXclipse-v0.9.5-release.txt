# WinXclipse v0.9.5

WinXclipse v0.9.5 is a major experimental update for Exynos/Xclipse devices. It adds configurable Apex frame generation, reorganizes the Vulkan wrappers, ports the newer Souza touch controls, improves the HUD, incorporates the applicable platform work documented in the Souza branch changelog, and fixes long-session virtual-controller lockups, recording-related audio loss, rumble routing, and several container, shortcut and input-editor crashes.

# Highlights

### Apex Frame Generation

- Added experimental GLES 3.1 frame generation for Vulkan containers.
- Frame Generation is configured inside Video Configuration for both containers and shortcuts; shortcut values can override the container without changing it.
- Added Fast, Balanced and Quality profiles with clear trade-offs:
  - Fast has the lowest GPU cost and latency, but may deform edges more often.
  - Balanced uses a larger motion search for a middle ground.
  - Quality reduces warped edges with more conservative blending, but costs more GPU time and may introduce blur or double images.
  - Existing Ultra Quality presets are migrated automatically to Quality.
- Added fixed 1.5x through 5x modes in 0.5x steps.
- Automatic mode targets a user-entered output FPS.
- Long explanations now live behind dedicated `?` buttons for Frame Generation and Profile instead of occupying the main screen.
- The in-session sidebar tile remains locked until Frame Generation is enabled in Video Configuration and the renderer is Vulkan.
- Persisted Frame Generation starts only after the Android EGL surface is stable, avoiding the shortcut crash loop seen when enabling it, exiting and reopening the game.
- Fixed Frame Generation incorrectly reporting that GLES 3.1 was unavailable on capable Samsung devices: the compositor now requests an explicit EGL 3.1 context, logs the returned version, and does not cache a capability check made before a current surface exists.
- Fixed the Xclipse compute compiler rejecting Apex with `image2D: No precision specified` after confirming the live Display dialog. Sampler/image precision is now explicit and unused uniforms no longer generate misleading warnings.
- Runtime Apex/shader failures disable the active state instead of leaving a false enabled indicator.
- Restored the stable fixed GLES Compute path from the older APK. Backend selection and native/automatic `libapex` activation were removed to avoid the vendor-driver `SIGSEGV` route. The Low Latency extrapolation mode was removed as well; frame generation always interpolates.
- Low Latency controls were removed from the sidebar and Video Configuration; saved values are ignored.
- The sidebar places FPS Limiter beside Frame Gen and HUD beside Display.
- The compact HUD counter is again shown only as `Apex <source FPS × effective multiplier> (<multiplier>x)`. It is not capped by display Hz and no longer adds the confusing second `real` value; measured real/generated compositor counters remain available to diagnostics.
- Optional HUD rows expose the measured Frame Generation latency estimate, Apex/shader failure state and actual `GEN FPS`. `GEN 0 FPS (no output)` clearly reports when Apex is enabled but is not producing synthetic frames; `ApexTelemetry` exposes the same counters in logcat.
- Generated draws now consume a finite budget earned by actual game Presents, including the correct fractional cadence for 1.5x. Apex stops scheduling when the budget is empty instead of redrawing a stale texture indefinitely and starving the game/BCN pipeline. GLES errors are sampled instead of synchronously queried after every game frame, avoiding an unnecessary GPU-queue stall.
- Apex keeps a finite synthetic-frame budget earned only from actual game Presents. Its display-clock scheduling follows the proven 0.9.5 path, avoiding the phase-sensitive headroom gate that could incorrectly reject every generated frame.

### Wrappers, ASTC and ETC2

- The new hybrid stack is `Wrapper-Default` and is selected for new containers; normal (non-transcode) sessions use this hybrid pair. ASTC/ETC2 transcode sessions, including RE3 Remake, use the proven Winlator Mali wrapper/layer pair instead, verified on Xclipse 940 with hundreds of ETC2 and 106 ASTC transcodes at ~1.2-2.2 GB/s.
- Old `Wrapper-BCN` and `Wrapper-Xclipse` selections migrate to `Wrapper-Default`.
- The previous generic `wrapper` selection migrates to `Wrapper-CMOD-V1`; the V2 path has its own stable `Wrapper-CMOD-V2` identity.
- Built-in choices are Wrapper-Default, Wrapper-CMOD-V1 and Wrapper-Kirimu.
- Wrapper-CMOD-V2 is available only through the existing Wrappers release.
- Wrapper-Leegao and Wrapper-GameNative are download-only and are not embedded in the APK.
- The existing Wrappers release contains CMOD V1, CMOD V2, Leegao, GameNative and Ref4ik-v6.
- The Downloads page reads the maintained wrapper release, downloads archives directly and installs them under stable identifiers.
- Community configs automatically recognize bundled wrappers and recover missing downloadable wrappers from Downloads or the remote catalog without recreating the config.
- Fixed ASTC/ETC2 transcoding activation so a requested transcode can enable the compute layer even when BCN emulation is set to None or Partial.
- Transcode sessions extract the proven Winlator Mali pair: the new wrapper hides ASTC unless `WRAPPER_BCN_ASTC` is set (black ASTC without it, still exported for the new stack), and its tracked BCN copy path deadlocks RE3 on Xclipse on the first emulated texture in every transcode mode (silent hang, 0% CPU). Stale wrapper BCN/ASTC variables are cleared on every boot, the BCN quality preset is exported when not `auto` (Mali 1.2 parity), and containers migrate between pairs automatically.
- The HUD reports `ARMED`, `LOADED`, `ACTIVE`, or a specific error for the effective BCN-to-ASTC/ETC2 path. `ACTIVE` is shown after a real transcode operation is logged, including the layer profile-line format, or after compute pipelines are created when a wrapper omits per-texture telemetry; layer mapping alone remains `LOADED`.
- Wrapper-Default uses the safer Mali shader-patch policy intended to avoid the wrapper-side pipeline crash observed in Red Dead Redemption.
- Experimental BCN is configured directly from the Graphics Driver gear. The established Leegao layer remains available as the default path, while the Xclipse-optimized BCN archive is a separate opt-in and is selected even when no explicit ASTC/ETC2 transcode mode is enabled.
- Wrapper-Kirimu keeps the exact legacy bundled binary and uses only its integrated BCN interface. Leegao-only cache/transcode controls are disabled for Kirimu, safe device creation is enabled, and its staging arena is bounded to 128 MB to reduce the reported RAM growth/retry loop without replacing the old wrapper.

### Controls

- Ported the Souza Final control refinements while preserving WinXclipse touch, mouse and vibration behavior.
- Kept the current spaced D-pad layout and restored the stronger original Souza halo requested for its petals.
- Added outward D-pad arrows, rounded glass controls, larger high-contrast labels and matching glow for buttons, sticks, trackpads and the RTS keyboard rows.
- Updated the analog response to Souza Final's 0.25 dead zone and 2.70 sensitivity, with the 1.6 touchpad base retained where no user preference overrides it.
- Moved the left stick of Virtual Gamepad 1 and 2 only slightly to the right, away from the display edge.
- Removed touchscreen-button haptic feedback and its switch as intended. Physical-controller game rumble remains enabled through the existing master/per-player controls and test button.
- Fixed the editable-template crash after changing a button icon: the icon cache now covers the complete Souza icon set and validates missing or invalid icons before drawing.
- Fixed long-session virtual-controller failures caused by confusing Android pointer indexes with pointer IDs. Multitouch cancellation now releases every active button and axis, publishes a neutral gamepad state, and cannot leave the character walking in the last direction.
- The touchscreen timeout follows its current setting, waits while any control or touchpad gesture is held, and neutralizes input before hiding the overlay.
- Physical-controller rumble now handles multi-digit Linux `eventN` devices, independent dual motors, repeated-effect throttling and reliable stop/cleanup, preventing ADB/USB renumbering or a missed stop from leaving vibration stuck.

### Display Sidebar and HUD

- The FPS Limiter tile now toggles the saved limit on and off.
- Its three-dot menu offers fixed 24, 30, 45, 60, 75, 90 and 120 FPS values plus Custom from 15 to 240 FPS.
- Removed the obsolete Unlimited choice; disabled state is shown as Off.
- Shortcut limiter changes stay on the shortcut instead of silently modifying its base container.
- The live Display panel can configure Frame Generation with the same profiles, multiplier and automatic target used by the container or shortcut.
- The main sidebar uses two compact rows: FPS Limiter beside Frame Gen, then HUD beside Display. Frame Gen follows the active Vulkan/Apex state.
- The HUD can show the container graphics API, DX wrapper, effective BCN transcode path and physical phone GPU.
- Phone GPU is shown above the SoC in the vertical HUD, and the redundant `Samsung` prefix is removed from the GPU name.
- Browser cover search for shortcuts now cleans executable suffixes, ranks the closest normalized game title, and skips matching entries that have no portrait artwork.

### FSR, Video and Effects

- AMD FSR 1.1 now reduces the guest desktop resolution before EASU, providing a real reduction in rendered pixels instead of upscaling a full-resolution frame.
- Live FSR quality changes resize the Wine desktop and active game window and recreate render targets, preventing clipping, zoom, and unintended black bars.
- FSR quality is saved through Video Configuration for containers and shortcuts; the sidebar shows the active state without silently replacing the saved preset, while texture filtering remains available live.
- FXAA, CRT, Toon, and NTSC effects are directly available in the Display sidebar. Brightness, contrast, and gamma remain grouped under Color Custom.
- vkBasalt CAS/DLS sharpening, strength, and denoise can be configured per container or shortcut and from Display; changes made during a session are saved and applied on the next launch.
- Added concise `?` help beside FSR Upscale and vkBasalt, explaining actual resolution, image-quality and GPU-cost trade-offs.
- Auto refresh rate requests the panel's highest supported mode; explicit 60, 90, 120, and 144 Hz choices select the matching mode when the panel exposes it.
- The HUD defaults to a monochrome layout with Show FPS, wrapper, GPU, CPU, RAM, battery, border, and SoC information selected. A one-time upgrade migration also turns Show FPS on for older saved layouts; later manual changes are preserved. Renderer/API visibility remains independently configurable.

### Additional Souza Changelog Items

- The Community Config install dialog uses the purple-bordered blurred style with a rounded 2:3 cover banner and a slightly narrower popup.
- New containers use the Intermediate FEXCore preset. XInput, DInput, and Exclusive XInput remain opt-in, and 32-bit WoW64 processes keep a separate CPU list with an all-core fallback.
- Texture Filter includes Bilinear, Nearest, FSR, and None; old FSR settings migrate to the current saved fields. Gyroscope input starts enabled, while LayerCache Helix stays opt-in.
- The combined DXVK/VKD3D configuration includes the DDraw wrapper selector and a None option that restores Wine's builtin ddraw.dll.
- Contextual help is available for theme, rotation, performance, DXVK/VKD3D, video, and graphics settings. Update checks are rate-limited so the prompt appears at most once every four days for a newer release.
- Experimental Performance starts with every individual optimization disabled. WoW64 performance-core pinning and Translation Turbo sit with the main system controls instead of being preselected inside the tuning popup.
- The HUD can show SoC load and GPU temperature and can disable the high-RAM blink/dialog. Modern 2340x1080, 2560x1440, and 3120x1440 display sizes are available to containers and shortcuts.
- Wine stdout, stderr, and exit status are mirrored to logcat for startup diagnosis. Control shaders, native X11 blits, input-shim lookups, EGL/JNI lookups, and the audio pacer include the Souza changelog's low-overhead paths.
- ARM64EC startup uses the current FEX bridge, WineD3D keeps the compatible GL route, the memory shim no longer leaks into the main native library, and fakeinput is size-verified before preload.

### Devices, Rotation and Interface

- Added Galaxy Tab S10 FE SM-X520 and SM-X526B detection.
- Added Galaxy Tab S10 FE+ SM-X620 and SM-X626B detection.
- All four models receive Exynos 1580 / Xclipse 540 handling even when early Android startup exposes only a generic GLES renderer.
- Community exports preserve the exact regional model suffix reported by Android and normalize known Samsung catalog metadata to the correct commercial device, Exynos SoC and Xclipse GPU names. Export now requires exactly one English compatibility state: `Boots but crashes`, `Menu only`, or `Playable`. The Mortal Sin SM-X520 config is corrected to Galaxy Tab S10 FE / Exynos 1580 / Xclipse 540.
- Shortcut and Community Config cover cards now clip the artwork into rounded top corners and join cleanly to the lower text panel. Community cards repeat the cover as a dark blurred label background, show compatibility instead of the phone model, and keep each game's config count at the lower-left above the label. Every dialog, popup, and dropdown shares the purple-bordered style in both themes.
- The Community Config install dialog shows a rounded portrait cover banner in a slightly narrower popup, and missing DXVK/Box64/FEXCore/VKD3D content is downloaded and installed automatically during import.
- Container pickers act directly when only one container exists; the About and backend Logs dialogs follow the same bordered style, and logs can be saved to Downloads besides being shared.
- All memory selectors now include 6, 8, 10 and 12 GB options, and the old 4092 MB value migrates to 4096 MB. Spinner and popup surfaces use the same purple outline in light and dark modes.
- Wine Light/Dark mode follows the effective Android app theme by default, still allows a per-container Light or Dark override, and selects the matching bundled WinXclipse wallpaper whenever Background is set to Image; manually imported wallpapers remain supported.
- Wine wallpapers fill the complete container desktop at every supported resolution instead of leaving a solid-color frame around a centered 480p image; non-16:9 modes use an aspect-preserving center crop.
- Wine sessions support normal and reverse landscape, allowing either long edge of the phone or tablet to face upward without enabling portrait rotation.
- Replaced the old update alert with a WinXclipse-styled AMOLED dialog that clearly shows installed and available versions.
- Corrected the application version display to `0.9.5`.
- Settings can switch to an optional alternative launcher icon without killing the app; the launcher may take a few seconds to refresh its icon cache.

### Stability and Rendering

- OpenGL/GDI startup keeps the required system GL libraries available instead of depending on the experimental BCN extraction path.
- Frame Generation is restricted to compatible Vulkan sessions and is rearmed after surface initialization.
- VSync, present mode and the FPS limiter remain independent settings.
- Mailbox remains the high-throughput tear-free path while FIFO, Immediate and Relaxed retain their explicit behavior.
- FSR, color effects and the Frame Generation compositor share validated render targets and fall back safely when a GPU rejects an intermediate format.
- Wine registry repair now validates the correct registry header and can recover every supported prefix source from invalid-registry and mismatched-wineserver startup failures.
- Raw Wine/Proton profiles skip unusable non-archive prefix packs instead of aborting container creation.
- The container Wine/Proton picker deduplicates the APK-bundled Proton 9 and its managed version-code `0` profile, so Proton 9 appears only once.
- Normal and Essential startup disable the optional PlugPlay, RpcSs and tablet-input services. Aggressive keeps controller-critical PlugPlay available while disabling RpcSs and tablet input; Proton prefixes without a tablet-input registry key also receive a short bounded `tabtip.exe` cleanup, reducing the active idle baseline to roughly seven or eight without touching controller discovery or rumble.
- PulseAudio keeps its daemon and Wine clients connected during recording, ADB/USB announcements and output-route changes. Recorder-only/source-only events are ignored; if Android disconnects AAudio, a debounced native bridge replaces only `module-aaudio-sink`, restores its state and moves existing game streams to it.
- File sharing and generated frontend launch metadata resolve the active package ID for all four APK variants. The default frontend export directory is now `Downloads/WinXclipse/Frontend`.
- D8VK 1.0 and the selected DXVK 1.10.3 async/ARM64EC payloads are bundled again, matching the visible defaults.
- Shortcut sessions wait for all non-base guest processes to disappear and then close after five continuous idle seconds; Wine services and crash-defender/reporting processes cannot keep an exited or failed game session open. An optional Wine lifecycle diagnostic records the reason, process snapshot, non-standard processes and recent guest output in `Downloads/WinXclipse/logs`.
- When lifecycle diagnostics are enabled, each container receives its own log directory with a general `wine_lifecycle` report plus separate timestamped DXVK and VKD3D logs. The feature remains disabled by default.
- Out-of-spec X11 PutImage requests no longer terminate Wine sessions through a fatal BadMatch path; packed cursor and mask uploads use their correct size.
- First-boot progress now advances through imagefs extraction, runtime installation, and finalization instead of appearing frozen.
- Native X11 2D operations process full 32-bit pixels, reducing byte-loop overhead on shared LPDDR memory.
- HUD RAM warnings use consistent 90% blink and 93% dialog thresholds across device memory tiers.
- The DXVK + VKD3D gear includes `RAM Fix`, enabled by default. GTA V receives the tested memory-streaming limits that prevent missing textures and shared-RAM/VRAM OOM freezes; disabling it removes only WinXclipse's exact managed values and preserves custom tuning.
- Confirmed container, shortcut and imported `dxvk.conf` settings are flushed to disk and atomically replaced. Cross-process locks and merge preserve newer settings when an older live instance saves runtime metadata; latest-state recovery mirrors restore missing/malformed indexes, and existing Wine-prefix data is made visible again with safe defaults if an older build lost its index.
- CPU-affinity checkboxes are centered in true rows of four on octa-core devices and five on deca-core devices in both container and shortcut settings.

## Status

### Functionally experimental

Frame Generation, wrapper behavior, ASTC/ETC2 transcoding and game compatibility vary by device, GPU driver, Android firmware, runtime and game. A wrapper appearing in Downloads does not guarantee compatibility with every device.
