# WinXclipse v0.9.1

This is an incremental update to WinXclipse v0.9 focused on Community Configs, Wine input and shortcut reliability, x86/x86_64 and 32-bit compatibility, smoother Wine navigation, and safer DXVK/VKD3D setup.

# What Changed Compared to v0.9

### Community Configs

- Added a Community Configs catalog backed by the dedicated GitHub release.
- Config ZIPs download automatically; users do not need to download or keep the ZIP manually.
- Added fallback through the public release-assets page, a saved catalog index, and validated offline cache when the GitHub API is unavailable or rate-limited.
- Added toolbar search by game name.
- On the first visit, a one-time AMOLED dialog explains how to export and submit tested configs and opens the project Discord directly.
- Equivalent names are grouped regardless of case, trailing spaces, punctuation, or Arabic/Roman sequel numbers through X.
- Every matching config is checked for an embedded cover before browser artwork is requested.
- Community covers can be replaced manually.
- Multiple configs for one game show device choices first, followed by phone, RAM, GPU, CPU, expected FPS, tester, notes, and optional container details.
- Export requires the game/container name, keeps the detected phone model fixed, removes the version suffix from the ZIP filename, and includes Discord handle, expected FPS, hardware metadata, notes, content requirements, and optional cover.
- Fixed config staging, bundled-content matching, import-close failures, and false missing-content warnings.
- Existing exported ZIPs automatically recover their external Xclipse driver from installed content, Downloads, or the maintained driver catalog; old exports such as Xclipse 920 Old do not need to be recreated.

### Wine Input and Shortcuts

- Touchscreen mouse handling was aligned with Winlator Mali for left/right clicks, dragging, pointer grabs, Wine context menus, and shortcut creation.
- Wine-created `.lnk` files now resolve quoted, relative, environment, Unix, and Wine paths correctly.
- Shortcut discovery refreshes executable targets, names, and artwork reliably.
- The controller startup notice was removed.
- Input Controls now includes controller auto-grab (plug and play), master vibration, and vibration testing.
- The obsolete touchscreen-haptic option and feedback path were removed.

### Runtime, DXVK, VKD3D, and 32-bit

- Bundled Box64 is now `0.4.3-260519-024717c`; old `0.4.4` selections migrate automatically.
- Fixed Proton x86_64 startup by preserving the shared Box64 executable, using the installed Wine path explicitly, and separating guest library paths from Android's native linker path.
- Conventional x86/x86_64 Wine no longer receives incompatible ARM64EC DXVK entries.
- Missing DXVK/VKD3D DLLs are verified and reinstalled instead of trusting a stale installation marker.
- Disabling VKD3D restores Wine's D3D12 files after DXVK extraction.
- Pure win32 prefixes keep 32-bit DLLs in `system32` and no longer create a synthetic `syswow64`; WoW64 prefixes still populate the required 32-bit side.
- Offscreen FSR/effect buffers retry with core RGBA when a driver rejects BGRA and fall back to direct rendering instead of showing a black screen.

### Performance and Responsiveness

- Wine 2D navigation uploads only changed drawable regions for small menu and selection updates.
- Padded-stride texture uploads are packed correctly.
- Present notifications no longer hold the drawable render lock during X11 event delivery.
- Opaque Wine/game windows and full-screen post-processing passes render without unnecessary blending.
- Fully covered windows below the highest opaque full-screen window are skipped while later popups remain visible.
- Repeated startup service rewrites and temporary diagnostic logging were removed from normal launches.
- Container filesystem deletion runs outside the UI thread.
- VSync modes `100%`, `50%`, and `Off` are available independently from the FPS limiter.
- Rockstar camera movement no longer shows horizontal tearing: synchronized modes force FIFO with real 100%/50% pacing, and Android presents complete compositor frames even when guest VSync is off.
- Proton/Wine entries appear immediately from local cache; catalog refreshes are throttled, unchanged DOS drive maps and shared PulseAudio files are reused, and storage-provider transfers use 64 KiB buffering.

### Additional Fixes

- Community/container creation no longer overwrites an existing `xuser-1` when manager state is stale.
- Valid on-disk container metadata is preserved during defensive saves.
- External Android storage and configured Wine drives are available in File Manager.
- Runtime/content names are deduplicated and old identifiers migrate automatically.
- MangoHUD mode uses the stable Android-native HUD path adapted from Bannerlator.
- Winlator HUD settings include battery percentage.
